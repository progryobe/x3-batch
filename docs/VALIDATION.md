# 検証結果 — 2026-10-07

## 実行環境

Linux x86_64 / Node 24.19.0 / Python 3.12 / Chromium 138.0.7204.0（headless）。本番ビルドを `/x3-batch/` のサブパスで静的配信し、実ブラウザで操作した。

## 結果

| 項目 | 結果 |
|---|---|
| Python参考版の既存7テスト | 全PASS。参考版のコードは未変更 |
| Webコア11テスト | 全PASS：XTH3種、XTCH、方向/パディング、UTF-8、境界、自然順、画像調整、ディザ、100件超のフォルダ列挙 |

| 通信チェック | アセットGETとローカルBlob表示のみ。画像処理中のfetch / XHR / WebSocket / POSTなし |

## 500枚試験

- 入力：1200×1800の画像500枚（JPEG400枚、PNG100枚）。実Fileをフォルダ入力へ渡した。
- 変換：528×792、Fit、Floyd-Steinberg、明るさ・コントラスト0。
- 生成：**31.9秒**（UI表示）。保存までのテスト測定は32,342ms。
- 出力：**52,291,312 bytes（49.9 MiB）**、500ページすべての索引・XTHヘッダー・MD5を検証。
- UI：生成中の50msタイマーが670回動作し、原画像への表示切替も応答。
- 仮想化一覧：500件読み込み時もDOMの表示行は25件未満。
- 中止：途中でWorkerを停止し、未完成の保存リンクがないことを確認。その後500枚で再実行して成功。
- 想定外のHTTP通信：0件。

詳細データ：`browser-benchmark.json`。速度はこの検証環境・開発用画像での1回の測定であり、全端末の速度保証ではない。RSSや各OSのGPU/画像デコーダのメモリは未測定。設計上同時に500画像をフル展開せず、Exportは1枚ずつ処理する。

最初の実行はテスト入力に空のPNGが1枚混ざっていたため、そのページで正しくエラー停止した。入力を修正して全試験を再実行し、上の結果を得た。通信テストでは画像用blob URLを外部送信と誤判定していた条件も修正し、HTTP通信とローカルBlobを区別した。

## 未検証と制限

- X3実機での表示・純正ファーム別対応。
- macOS / Windowsの通常ウィンドウでの手動操作と実画像500枚。
- Safari / Firefox、モバイル端末。主要対象はデスクトップChrome / Edge。
- 任意の画像に対するPillowとの画素単位一致（Canvasの縮小フィルターとFSの丸め差）。形式の一致とは別。
- GitHub Pagesの実公開状況は `DEPLOYMENT.md` に記録する。

画像の外部送信は実装していない。GitHub Pagesへ送るのはアプリのコードと開発用goldenテスト画像だけであり、利用者が選ぶ画像ではない。
